   - **Resolution**: The password hash algorithm was updated, but session tokens were not invalidated. The solution involved clearing all active sessions and forcing re-authentication. Additionally, automatic session cleanup was implemented on password changes.

2. **Two-factor authentication codes not working (Ticket ID: TICK-016)**:
   - **Problem**: Users were unable to log in using TOTP codes from authenticator apps, with codes being marked as invalid even when entered immediately after generation. This affected a random subset of users.
   - **Resolution**: The issue was traced to server time drifting by 2 minutes due to misconfigured NTP, which caused TOTP codes to fall outside the acceptance window. The resolution included configuring NTP synchronization, verifying time accuracy, adding time drift monitoring, and increasing the TOTP acceptance window to ±1 time step.

3. **SSO authentication broken after upgrade (Ticket ID: TICK-011)**:
   - **Problem**: The Single Sign-On integration with the corporate SAML provider was failing, resulting in users receiving an 'Invalid SAML response' error after being redirected back from the SSO portal. This issue began after a version upgrade.
   - **Resolution**: The upgrade changed the default SAML signature algorithm from SHA-1 to SHA-256, which required an update to the IdP configuration. Coordination with the IT team was necessary to update the IdP settings, and a configuration option was added to specify the signature algorithm.

These tickets highlight common authentication issues and their resolutions, which can guide troubleshooting efforts.
